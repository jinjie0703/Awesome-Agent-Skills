# 📐 Bug Hunter 根因排查 (RCA) 标准操作手册

本文档为 AI Agent 排查疑难杂症、线上偶发崩溃与高并发 Bug 提供严密的 5 步排查推导范式。

---

## 🏛️ 5 步根因推导法 (Root Cause Analysis SOP)

### 1. 现象与边界特征锁定 (Phenomenon & Boundary)
- **输入异常表现**：错误码、HTTP 5xx、死锁、OOM 崩溃还是数据脏读？
- **时间与并发特征**：是启动即崩溃（确定性），还是特定流量高峰期偶发（并发竞争 / 资源耗尽）？

---

### 2. 堆栈指纹与时序还原 (Stack Fingerprint & Timeline)
- 提取最深层 Root Cause 异常；
- 剥离第三方框架样板代码，锁定最先触发异常的**业务代码文件名与行号**。

---

### 3. 根因假设树 (Hypothesis Tree - ASCII 纯文本)
列出最可能的 2~3 种底层机理假设，并设计快速验证手段：

```text
               ┌── 假设 A: 数据库连接池耗尽 (HikariPool / Redis Timeout)
               │          └─ 验证方法: 检查连接未归还或长事务阻塞
               │
  [崩溃根因] ──┼── 假设 B: 高并发并发写 Race Condition (未加分布式互斥锁)
               │          └─ 验证方法: 查看并发线程 ID 与相同 Key 冲突时间戳
               │
               └── 假设 C: 序列化/反序列化类型不兼容 (字段增删变更)
                          └─ 验证方法: 打印入参 JSON 原文结构
```

---

### 4. 最小可复现用例 (Minimal Reproducible Example - MRE)
- 编写 10~20 行脱水脚本，剥离所有复杂的业务表和上游 RPC 依赖；
- 能够 100% 稳定复现出与报错现场一致的异常堆栈。

---

### 5. 工业级防御性修复与复盘 (Defensive Patch & Post-Mortem)
- **不仅治标**：修复导致当前崩溃的代码逻辑；
- **更要治本**：加入超时控制、幂等兜底、边界默认值或断路熔断；
- **长效防线**：编写一组防回归的单元测试用例。
