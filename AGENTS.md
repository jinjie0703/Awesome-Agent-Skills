# 🤖 AGENTS.md - AI Agent Contribution & Development Protocol

> **Notice for AI Coding Assistants & Autonomous Agents**:  
> Please read and follow these strict engineering guidelines when extending, refactoring, or contributing new skills to this repository.

---

## 1. 📂 Architecture & Directory Standard (目录与双轨规范)

Every AI Agent Skill MUST reside in a dedicated folder under `.agents/skills/<skill_name>/` and strictly adhere to our **Dual-Track Protocol**:
- `SKILL.md`: The brain-computer interface document specifically for autonomous agents. Keep instructions exact, concise, and structured (include Env Check, SOP steps, and CLI parameters). Do NOT write fluffy background stories here.
- `README.md`: The product showcase document for human developers, detailing the pain points solved, architecture diagram, and quickstart examples.
- `scripts/`: Python utility scripts must be atomic, modular, and CLI-accessible.

---

## 2. 🛡️ Industrial Guardrails & Safety Rules (安全与防错红线)

When writing or updating any Python scripts for skills (e.g., Word, Excel, PDF manipulation):
1. **Environment Check & `uv` Priority**: Always provide instructions to check dependencies via `python -c "import xxx"` and recommend `uv pip install --system <package>` for blazing-fast system installation.
2. **Mandatory Backup Mechanism**: Any script that modifies a user's local file MUST automatically generate a `filename.bak.ext` backup copy before writing changes.
3. **Never Hardcode Paths**: Always use `pathlib.Path` and automatically create parent directories via `.mkdir(parents=True, exist_ok=True)`.

---

## 3. ✍️ Strict Git Commit Message Convention (Git 提交规范)

All commits generated by humans or AI MUST follow the **Conventional Commits** specification:
`<type>(<scope>): <subject>`

### Accepted Types (`<type>`):
- `feat`: Adding a brand new skill or a major new feature to an existing skill (e.g., `feat(docx_editor): add table formatting support`)
- `fix`: Fixing a bug or crash in a script (e.g., `fix(docx_editor): resolve rPr null attribute crash`)
- `docs`: Updating `README.md`, `SKILL.md`, or documentation tables (e.g., `docs(skills): update repository overview table`)
- `refactor`: Code restructuring without changing external behavior (e.g., `refactor(docx_replace): optimize run splitting logic`)
- `chore`: Maintenance, dependencies, or `.gitignore` updates (e.g., `chore: add uv check to pre-flight instructions`)

### Scope (`<scope>`):
Use the exact folder name of the skill being modified (e.g., `docx_editor`, `project_deep_diver`, `skills`).

### Subject (`<subject>`):
- Write in lowercase (unless proper nouns).
- Be concise and clear (under 50 characters).
- Do not end with a period `.`.
